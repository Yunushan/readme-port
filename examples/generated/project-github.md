Northstar turns service health, deployments, incidents, and ownership into one readable view. It is designed for small platform teams that need trustworthy context without another heavyweight control plane.

## At a glance

| Capability | What it gives you |
| --- | --- |
| **Service map** | See ownership, dependencies, health, and recent changes together. |
| **Incident context** | Turn alerts into a short, ordered trail of useful evidence. |
| **Portable deployment** | Run locally, in containers, or on Kubernetes without a hosted dependency. |

## Built with

| Technology | Role |
| --- | --- |
| **Node.js** | API and background jobs |
| **PostgreSQL** | Durable operational data |
| **OpenTelemetry** | Vendor-neutral signals |

## Quick start

```bash
git clone https://github.com/example/northstar.git
cd northstar
cp .env.example .env
docker compose up -d
```

## Installation

### 1. Configure the environment

Copy the example file and set the database connection.

```bash
cp .env.example .env
```

### 2. Start the stack

Build and launch the services.

```bash
docker compose up -d --build
```

## Usage

### Check system health

The health endpoint is safe for container and load-balancer probes.

```bash
curl http://localhost:8080/health
```
